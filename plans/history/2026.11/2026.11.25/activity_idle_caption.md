# Activity idle caption and all-chats default

The Activity diagram followed only the focused chat (single-chat mode was the default), so when that chat was waiting for the user nothing flashed and the section looked hung, while other chats were visibly running in the session list. Nothing on screen named the followed chat or said it was idle.

## Changes

- **Idle caption** (`src/activityIdle.ts`, new): pure, vscode-free `idleText`, `othersWorking`, `isWorking`. Caption reads `<title> — <state>` plus `· N other chat(s) working`. States: running = working, waiting = waiting for you, background = background tasks running, other = idle. A chat whose dot carries `background` in `also` (behind waiting/unread) counts as working and its text gains `· background tasks running`. Titles cut at 60 code points (emoji-safe). Strings live in `IDLE_STRINGS` with `{0}` placeholders and whole-string singular/plural; the host passes `vscode.l10n.t` as translator.
- **Host** (`src/activity.ts`): `registerActivity` takes `idleInfo(id)` and returns `idle()`. `sendIdle` posts `{type:'idle', text}` only on change (`idleSig`). Sent at each `poke`; `idle()` (called from the watcher's `onChange` via `Provider.idleHook`) sends only while the section is visible and open, and skips while a chat switch is pending (`currentId() !== shownId`) so `poke()` owns reset-then-idle ordering.
- **Page** (`src/activityHtml.ts`): keeps `idleText` and `liveText`; `caption('')` falls back to the idle text, so live captions win. `wait` events now clear the live caption so "waiting for you" is not hidden behind the last message's caption. `reset` clears both. The browser view never receives `idle`, so its caption is unchanged.
- **Default** (`package.json`): `saropaChats.activity.allChats` defaults to `true`.
- **Checks** (`scripts/checks/check_activity.js`): idle wording singular/plural and no-title forms, `also` background handling, emoji truncation, translator coverage, `othersWorking` with `also`, manifest default `true`.

## Known limits

- Superseded by "Hardening and click-to-focus" below: a chat with no open tab now gets its title from the worker index (`TitleCache`), and `scripts/checks/check_activity_page.js` drives the page's `idle` / `wait` / `end` / `reset` handlers in a stub DOM. The remaining limits are listed in that section.

## Verification

`npm run compile`; `node scripts/checks/check_activity.js`, `check_webview.js`, `check_browser.js` — all OK.

## Hardening and click-to-focus

### Hardening

- **Malformed dots** (`src/activityIdle.ts`): a private `statesOf` reads a dot defensively (non-object dot, non-string `s`, missing or non-array `also`, non-string entries). `isWorking`, `othersWorking` (also with a missing map) and the caption's state wording all go through it, so such a dot reads as idle and never throws.
- **Switch-skip ordering** (`IdleGate` in `src/activityIdle.ts`): the reset-before-idle rule moved out of `registerActivity` into a pure class. `poke(cur, msg, keepPills)` returns `reset` then `idle` on a chat switch; `idle(cur, msg)` returns nothing (and does not build the message) while `cur` differs from the shown chat; `forget()` replaces the old `shownId = ''; idleSig = ''`. `src/activity.ts` sends what the gate returns. Exercising `registerActivity` itself would need a stubbed `vscode` module, which no check in the repo has; the gate is tested instead.
- **Title fallback** (`TitleCache` in `src/activityIdle.ts`, wired in `src/extension.ts`): when the followed chat has no tab title, the title comes from the existing worker request `apiChat` (soft request; its reply carries `title`), so no new request type was added. One lookup per id, cached; a lookup in flight is not repeated; a miss or failure is retried at most every 30 s. A cached title older than 5 min (`ttlMs`) is still shown but refreshed in the background; only a new or changed title calls `activity.idle()`, which re-sends the caption. The `AutoTitler` rename callback calls `titles.set(id, title)` (and `activity.idle()`), so a rename shows at once; `set(id, '')` invalidates an entry. `Provider.idleHook` (dot changes) first calls `titles.prune([...liveIds, currentId()])`, so the cache holds only live chats plus the followed one. The tab title still wins when present. The cache is created before the `AutoTitler` so its callback can reach it.
- **allChats default**: a comment at `ALL_KEY` and `allOn` in `src/activity.ts` and the CHANGELOG entry state that the `true` default applies only where no value is set, so an explicit `false` in user, workspace or folder settings is kept.

### Click-to-focus

- The idle message is now `{type:'idle', text, go, looking}` (`idleMsg`). `go` (button label, `IDLE_STRINGS.focusOther`) and `looking` (click-time text) are non-empty only when `others > 0`, i.e. when the "N other chats working" hint is in the text. All strings are in `IDLE_STRINGS` and pass through the host translator (`vscode.l10n.t`).
- Page (`src/activityHtml.ts`): the caption row comes from one helper, `captionHtml()`, used by the standalone page, the browser view and the sidebar section (`src/webviewActivity.ts`): `#caprow` holds the aria-live text `#cap` and a native `<button id="capgo">` (arrow glyph, `aria-hidden`), outside the live region. `drawGo()` (run by `paint()`) shows the button while the idle text with `go` is on screen and keeps it shown but `aria-disabled="true"` while a click is in flight, so keyboard focus stays on it; Enter and Space work natively. `title`/`aria-label` = `go`. While enabled, the caption text has class `go` and a mouse click on it works too. `goOther()` sets `capPending` and disables the button synchronously before posting `{type:'actFocusOther'}`, so a double click inside the 500 ms paint window posts once. A click shows `looking` at once; a `note` message shows the host outcome (class `bad` for errors) and falls back to the idle text after 4 s. `caption(text, fromNote)`: any caption that is not an outcome clears the outcome timer and the in-flight state, so the timer cannot later wipe a real live caption. `end` (last call), `wait` and `wake` go through `settleCaption()`, which leaves an active outcome alone; `wait` also clears only when no call is pending. `reset` hides the button and clears the click state. Listeners use `addEventListener` (no inline handlers). CSS uses `--vscode-textLink-foreground`, `--vscode-focusBorder` and `--vscode-errorForeground`.
- Host reach: the shared script holds `const toHost = null;`; only `activitySection` swaps in `vs.postMessage` (guarded by `typeof vs`), so the standalone page and the browser view cannot become clickable, and the browser view never receives `idle`. The function is named `capNote` because the browser page shell already declares `const note`.
- Host (`src/activity.ts`, `src/extension.ts`): `Provider.onMessage` routes `actFocusOther` to `activity.focusOther()`. It collects the other working chats from the dots, reads each one's transcript mtime (`BgTracker.fileOf` + `fs.promises.stat`) and picks with the pure `pickBusiest`: running before background (in `s` or `also`), then most recent mtime, then id. It posts `Opening <title>…` and calls `provider.tryResume(id)`; no working chat gives `No other chat is working now`. `openChat` (`src/resume.ts`) now resolves `true` when the panel command or the URI fallback took the chat and `false` otherwise (invalid id included), with its toast and log lines unchanged. `Provider.tryResume` returns that result; `Provider.resume` stays `Promise<void>` for every other caller (list, warner, usage, editor view, Open Work, browser view). A `false` result or a throw (logged) posts `Could not open <title>`.

### Checks

- `scripts/checks/check_activity_page.js` (new, registered in `vscode:prepublish` after `check_activity.js`): runs the real page script in the `webview_harness.js` stub DOM with its fake clock (each step advances 600 ms past the 500 ms throttle; `document.querySelector` returns one stub per selector so `wait` reaches its group). Standalone page: idle text without live caption, live caption wins, idle update under a live caption, `end` with and without pending calls, `wait` drops a stale live caption, `reset` clears both, missing `text`. Standalone also: `wait` while a call is pending keeps the live caption, and the button stays hidden. Section page (built from `captionHtml()`): button shown and enabled with the hint, label on the button, live region not a button, native button markup, listeners present, double click inside the paint window posts once and disables synchronously, button stays shown and disabled while in flight, no post from the outcome text or a live caption, `wait` / `end` / `wake` keep an active outcome, outcome falls back to the enabled idle caption after 4 s, a live caption that replaced an outcome is not wiped by its timer, `wait` without an outcome returns to the idle text, error note, button hidden without `go`, `reset` hides the button.
- `scripts/checks/check_activity.js`: malformed-dot cases, `pickBusiest` ranking and exclusions, `idleMsg` fields and translator, no first-person strings, `IdleGate` ordering, `TitleCache` (single lookup, cache, miss retry after `retryMs`, failure not cached, empty id; TTL refresh returns the stale title, is not repeated in flight, announces only a changed title, keeps the last good title on a miss; `set` without a lookup and `set(id, '')` invalidation; `prune` of titles and miss back-off), page wiring and theme-token strings. The async `TitleCache` block is awaited before the final verdict.
- A mutation run against a copy of `out/` (wait no longer clearing the caption; `IdleGate.idle` no longer skipping) made both checks fail.

### Known limits

- `registerActivity` and `focusOther` are not run under test (no `vscode` stub); the click round trip host-side (`actFocusOther` to `resume`) is unverified in a running VS Code.
- Enter / Space on the native button are not simulated in the stub DOM (it has no default actions); the check asserts the control is a `<button type="button">` instead.
- Keyboard focus staying on the disabled button is inferred from the button never being hidden while in flight; the stub DOM has no focus model.
- `apiChat` builds the whole chat summary (tokens, files) to return one title; it runs at most once per untitled chat per 30 s.
